北斗协议里的「功率」是**四类独立信息**，语句、方向、用途都不同，混用是常见错误来源。

## ① 卫星功率 —— `$BDGSS`

字段名直接叫「功率」的只有这一条，**仅全球短报文模块输出**，默认 1 秒 1 次。

```
$BDGSS,02,32,41,39,45,13,32,41,65,198*79
```

| 字段 | 含义 | 取值 |
|---|---|---|
| ① | 可用卫星数量 | 0~14，为 0 时后面字段全空 |
| ② | 入站卫星号 | 0~64，**0 = 没有合适的入站星** |
| ③~⑫ | 按①的数量循环，每颗星 4 个字段 | 卫星号 1~64 / 信号强度 / 仰角 0~90° / 方位角 0~360° |

三个使用要点：

- **仰角 + 方位角是它独有的**。`$BDSTA` 位 12 明确写着「可通过查询入站卫星信息，来确认卫星方向，防止遮挡」——这就是 `$BDGSS` 的存在意义：知道该往哪个方向架天线。方位角 **0=正北、180=正南、顺时针**，所以在中国境内仰角够用的星，方位角基本落在**南偏东到南偏西**这一片。
- **② 入站卫星号 = 0 是硬故障信号**：可见星不为 0，但没有一颗可作入站，说明当前波束/频点没有可用上行链路，此时发什么都会失败。
- 只有全球模块能用。区域模块只能靠 `$BDSNR`/`$BDSIG` 看波束。

## ② 区域波束功率 —— `$BDSNR` / `$BDSIG`

| 语句 | 内容 | 备注 |
|---|---|---|
| `$BDSNR` | 1~21 号波束跟踪状态，强度 **十六进制 00~4F** | **默认输出**；22~28 号需 `$CCDBG,snrlen,1` |
| `$BDSIG` | 已锁定波束的**数量 + 波束号 + 强度** | 数据量小，适合嵌入式 |

**两者互斥，二选一**，用 `$CCDBG,snrtype,0`（切 BDSNR）/ `$CCDBG,snrtype,1`（切 BDSIG）切换，设置后自动保存。

## ③ 功率调整（你自己的发射功率）

这是**反方向**的信息——中心站下发、调节你的上行功率：

- 输出语句 `$BDSTA` **指示位 9「功率调整通知」**，或查询 `$CCSTA,9`
- 取值 1~16，**共 16 档，每档 0.5dB**：1 = 下调 0.5dB，16 = 下调 8dB
- **重启后失效**，不落盘

另外 `$BDSTA` 位 6「发射开始通知」带一个**发射功率 0~17**，这是协议里唯一直接反映「本次实际发射功率」的字段（17 = 使用功放最大功率）。调天线时可以对着它看调节效果。

**提取结果（逐字转录）**

```c
#define LOG_OUT  QtDebugMsg

#define GET_BIT(x,bit)  (((x) & ( 1 << (bit))) >> bit)

#define CN_MAX_COUNT_LEVEL1  (43  - 1)
#define CN_MAX_COUNT_LEVEL2  (114 - 1)
#define CN_MAX_COUNT_LEVEL3  (323 - 1)
#define CN_MAX_COUNT_LEVEL4  (498 - 1)
#define CN_MAX_COUNT_LEVEL5  (1000 - 1)

#define EN_MAX_COUNT_LEVEL1  (86  - 4)
#define EN_MAX_COUNT_LEVEL2  (228 - 4)
#define EN_MAX_COUNT_LEVEL3  (646 - 4)
#define EN_MAX_COUNT_LEVEL4  (996 - 4)
#define EN_MAX_COUNT_LEVEL5  (2000 - 4)

#define TT_MSG_LEN      70
#define TT_MSG_LEN_8BIT 140
```

**中文释义（结合前面整理的北斗协议口径）**

| 宏 | 含义 |
|---|---|
| `LOG_OUT` | 日志输出宏，绑定 Qt 的调试输出级别 `QtDebugMsg` |
| `GET_BIT(x,bit)` | 取 `x` 的第 `bit` 位（先左移 1 到目标位做与运算，再右移回来得 0/1） |
| `CN_MAX_COUNT_LEVELn` | **通信等级 n 下可发的汉字数上限**（n=1~5 对应北斗卡通信等级 1~5），`-1` 是预留开销位 |
| `EN_MAX_COUNT_LEVELn` | **通信等级 n 下可发的 ASCII 字符数上限**，`-4` 是报文头开销 |
| `TT_MSG_LEN` | 单条短报文基础长度 70 字节（= 560 bit，即**全球短报文上限**） |
| `TT_MSG_LEN_8BIT` | 同一条报文按 8bit 字节表示时的长度 140（70 字节转十六进制可见字符后的长度） |

**两个可验证的硬结论**

1. **CN 与 EN 是同一容量的两种计法**：汉字按 14bit/字、ASCII 按 7bit/字，换算后各级完全相等——
   `43×14 = 86×7 = 602bit`（L1）、`114×14 = 228×7 = 1596bit`（L2）、`323×14 = 646×7 = 4522bit`（L3）、`498×14 = 996×7 = 6972bit`（L4）、`1000×14 = 2000×7 = 14000bit`（L5）。
2. **LEVEL5 = 14000 bit，正好是北斗三号区域短报文单条通信长度上限**（与手册 `$BDSTA` 位 10 卡限制信息里「区域通信长度 0~14000bit」吻合）；汉字 14bit/字也与 `$CCMSG` 汉字通信「每汉字占 14bit」一致。

也就是说这段代码就是一张**北斗三号卡等级 1~5 的报文容量映射表**：卡等级越高，单条能装的字越多，最高档 1000 汉字 / 2000 字符。`TT_MSG_LEN 70` 则对应全球短报文 560bit 的情况。

一点存疑标注：`EN` 按 7bit/字符是我从数值反推的（协议手册明文只写了汉字 14bit），`-4`/`-1` 的具体开销构成（报文头占用）手册未给出，**待核实**。
