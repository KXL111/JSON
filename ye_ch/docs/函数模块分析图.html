CommGateway 函数模块分析

按层、按任务、按函数三个粒度看工程结构。标 新增 的是 04 版新加的模块或函数，标 改动 的是 04 版改过的。05 版移植到 STM32F407ZGT6，只换了硬件驱动（以太网、串口、看门狗、随机数、日志串口，见 README 第 0 节），图表里的外设名和驱动函数名已按 05 更新，网口初始化那一行的 改动 指 05 的改动。函数名链接到《运作流程详解》的函数索引。

1. 分层结构

上层只调用下层；协议层是纯函数（不碰硬件、不碰任务），驱动层把每种硬件包在一个文件里。

2. 任务与数据通道

每个业务任务只碰自己的链路；任务之间只有三条通道：两个队列、一张加锁的状态表。

3. 函数调用关系（按任务）

左列是调用树，右列是说明。任务名 表示函数运行在哪个任务里，⇢ 表示经过队列 / 信号量交给别的任务。

6. 关键数据结构

6.1 text_msg_t —— 任务之间唯一的消息（app_msg.h）

typedef struct {
    text_kind_t kind;                   /* TEXT_SEND 终端→设备 / TEXT_RESULT 发送结果 / TEXT_RECV 收到的短报文 */
    dev_id_t    dev;                    /* DEV_BD / DEV_TT */
    char        msg_id[APP_ID_LEN];     /* 终端请求的 msg_id，回执时原样带回；TEXT_RECV 时为空，由 TERM 生成 UUID */
    char        taskid[APP_ID_LEN];     /* 同上 */
    char        peer[APP_PEER_LEN];     /* 发送：收信方号码；接收：发信方号码 */
    int         status;                 /* 仅 TEXT_RESULT：0 成功，1 失败 */
    char        text[APP_TEXT_LEN];     /* 正文（UTF-8，最多 3072 字节）；TEXT_RESULT 时是失败原因 */
} text_msg_t;                           /* 约 3.2 KB，按值拷进队列 */

6.2 dev_status_t —— 设备状态总表（dev_status.h）

dev_status_t
├─ bd : bd_status_t
│   ├─ status   0 在线 / 1 离线（SQ 为 0）/ 2 异常（串口 5 s 没有有效语句）   ← update_signal()
│   ├─ msg      空
│   ├─ cd       全球短报文服务频度（秒）                                       ← on_icp()
│   ├─ sq       0~4                                                            ← update_signal()
│   ├─ maxlen   汉字上限（CN 表）                                              ← on_icp()
│   └─ card : bd_card_t { valid, id, freq_region, freq_global, len_level, len_cn, len_en }
├─ tt : tt_status_t { status, msg, sq, maxlen }      天通接入后由 tt_task 写，现在 status = 1
└─ task : task_state_t { taskid, progress }          心跳的 taskstate      ← set_task_state()
