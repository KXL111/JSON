北斗协议语句详解

围绕北斗 RDSS（卫星短报文）模块的串口语句，讲清 读卡 / SQ / TCQ / FKI / TCI 这五件事：各为了获取什么、怎么获取（谁发、发什么、收什么），并给出真实格式的举例。字段口径与本项目 README.md、design.txt 一致。

0 全景：五件事与一句话职责

北斗模块挂在 RS422（USART6，38400）上。本机发给模块的语句以 $CC… 开头，模块回给本机的以 $BD… 开头；解析只看后 3 个字母，不看发送方标识。

名称语句方向为了获取什么怎么触发
读卡 $CCICR → $BDICP 本机→模块 / 模块→本机 卡号、区域/全球服务频度(CD)、通信长度等级(maxlength)、收发权限 上电后每 5 s 发一次查询，收到 ICP 即停
SQ $BDGSS + PWI 模块→本机 信号质量等级 0~4，并据此定 status（在线/离线/异常） 模块每秒自动输出，被动解析
TCQ $BDTCQ 本机→模块 把一条短报文发出去（请求发射） 终端下发 42212 → 组包成 TCQ 发出
FKI $BDFKI 模块→本机 上一条 TCQ 的发射结果（成功/失败、失败原因、还要等几秒） 发完 TCQ 后等它，10 s 没来算超时
TCI $BDTCI 模块→本机 别人/中心发来的短报文内容（收报） 模块随时上报，被动解析
一句话分清：读卡问"这张卡能干什么" → SQ看"现在信号行不行" → TCQ"我要发" → FKI"发没发成" → TCI"有人给我发了"。

读卡 ICR / ICP — 读北斗卡的身份与能力

① 为了获取什么

  • 卡号 bd_id（本机北斗号码，7 字节）。
  • 服务频度 CD：区域与全球各一个"最短发送间隔"。有权限才记频度，没权限记 0。上传取全球频度。
  • 通信长度等级 maxlength：1~5 级，决定单条最多能发多少字（查 design.txt 的 CN/EN 表）。上传取 CN（汉字数）。
  • 区域 / 全球的收发权限（没权限就别发，发了也被拒）。

② 怎么获取

本机主动问、模块回答。上电后每 5 s（CFG_BD_ICR_RETRY_MS）发一次查询语句，收到一次 ICP 就不再问。

本机发 $CCICR,0,00          // 查询卡信息，固定参数
模块回 $BDICP,...,卡号,...,区域权限,区域频度,长度等级,...,全球权限,全球频度,...*hh

③ ICP 关键字段（本项目口径）

字段含义映射到
第 13 字段区域收发权限有权限才记区域频度，否则区域 CD=0
第 14 字段区域服务频度（秒）区域 CD
第 15 字段通信长度等级 1~5maxlength（查 CN/EN 表）
第 17 字段全球短报文权限有权限才记全球频度，否则全球 CD=0
第 18 字段全球服务频度（秒）全球 CD（上传用这个）

④ 举例

// 第 15 字段 = 3 → 通信长度等级 3
design.txt: CN_MAX_COUNT_LEVEL3 = 323-1 = 322 个汉字   EN = 646-4 = 642 个字符
// 第 18 字段 = 60 → 全球每 60 s 才能发一条
→ 心跳里：CD=60，maxlength="322"（字符串，含汉字数）
读卡成功 = 本机知道了"我是谁、我能发多长、多久能发一次"。这三样是后面 TCQ 发报的前提。

SQ 信号质量 — 现在能不能发、在不在线

① 为了获取什么

  • SQ：信号质量等级 0~4（design.txt 口径，0 最差、4 最好）。
  • 由 SQ 派生 status：串口 5 s 无有效语句 → 2 异常；否则 SQ=0 → 1 离线，SQ>0 → 0 在线。

② 怎么获取

不用问，模块每秒自动输出卫星/波束信息，本机被动解析、每秒刷新。用两路信息折算：

  • GSS（全球模块）：$BDGSS 第 1 字段 = 可用卫星数量。
  • PWI（新体制波束）：波束锁定数量。
  • 算法：每一路取 min(数量, 4) 封顶成 0~4；两路都有取平均（四舍五入），只有一路就用那一路；超过 5 s（CFG_BD_SIGNAL_STALE_MS）没更新的不算；串口异常时 SQ=0。
为什么不用旧体制：只取旧体制出站波束时 SQ 恒为 0，所以改用新体制波束锁定数（bd_task.c 的 on_pwi()）。等级封顶策略在 sig_level() 里，实测后可调。

③ 举例

$BDGSS,02,32,41,39,45,13,32,41,65,198*79
          └┬┘
       可用卫星=2  →  min(2,4)=2

PWI 波束锁定=3       →  min(3,4)=3
两路平均 (2+3)/2 = 2.5 → 四舍五入 SQ=3 → status=0（在线）

// 若 GSS 第 1 字段=00 且 PWI 无锁定 → SQ=0 → status=1（离线）
// 若串口 5 s 没有任何有效语句   → status=2（异常）

TCQ 发报 — 把短报文发出去

① 为了获取什么

它不是"获取"，而是动作：向模块请求把一条短报文发射出去。发射的结果要看下一节的 FKI。

② 怎么获取（怎么发）

终端下发 42212 → 北斗任务 bd_submit() 组包成 $BDTCQ → 串口 DMA 发出。混编方式（编码类型 3，汉字段以 A4 前缀的十六进制承载）。一次只发一条，必须等到 FKI 才发下一条。

$BDTCQ,target_id,2,2,3,A4…报文数据…,0*hh
         │         │ │ │  └ 报文数据（混编：A4+十六进制 GBK）
         │         │ │ └ 编码类型 3 = 混编
         │         │ └ 入站确认申请 = 2   (CFG_BD_TCQ_CONFIRM)
         │         └ 频点 = 2             (CFG_BD_TCQ_FREQ)
         └ 对方卡号

③ 举例

// 给卡号 1234567 发一条混编短报文
$BDTCQ,1234567,2,2,3,A4...,0*hh
→ 串口 DMA 发出（1000 汉字约 4.1 KB，38400 下约发 1.1 s）
→ 进入"等 FKI"状态
本机最多处理 1000 个汉字（约 2000 字节 GBK）。是否超过卡等级上限由模块判断，结果通过 FKI 回来。发送期间北斗任务照常收数据、喂狗。

FKI 回执 — 上一条 TCQ 发没发成

① 为了获取什么

  • 上一条 TCQ 的执行情况：成功 Y / 失败 N。
  • 失败时的原因码与还要等待的秒数（频度控制）。
  • 由此维护 bd_fki（RD 发送间隔 / 剩余空闲时间，0=空闲、非 0=还要等）。

② 怎么获取

发完 TCQ 后被动等 $BDFKI。超时 CFG_BD_FKI_TIMEOUT_MS = 10 s（从"发完"算，另加串口发送时间）。只认指令名为 TCQ 的 FKI（OFQ/EPQ/QRQ 等也会出 FKI，忽略）。

$BDFKI,时间,指令名称,执行情况,失败原因,等待时间*hh

③ 举例与处理

FKI 实例含义本机处理
$BDFKI,032025,TCQ,Y,0,0*77TCQ 发射成功回终端 status 0
$BDFKI,032816,TCQ,N,1,7*6E失败：原因 1=频度未到，7=还要等 7 秒status 1，BD send too frequent, wait 7s
其他失败原因手册未列出status 1，BD rejected, FKI reason x, y 原样带回
10 s 没来 / 串口 1.5 s 没发完超时 / 串口忙回失败，BD serial busy
存疑：手册只给了一个失败示例 N,1,7，"1=频度未到、7=等待秒数"是按所在章节推断；其他原因码实测后在 on_fki() 里补。电量不足时模块表现为 $BDFKI 第 4 字段 = 2（见 design.txt）。

TCI 收报 — 别人发给我的短报文

① 为了获取什么

获取入站短报文的内容（中心站或其他卡发来的报文），解析后推给终端（42214）。

② 怎么获取

模块随时上报 $BDTCI，本机被动解析、解码、转码：

  1. 读编码类型字段。
  2. 类型 3（混编）：去掉 A4 前缀，按十六进制还原成 GBK；其他类型：数据本身就是 GBK / ASCII。
  3. 统一转成 UTF-8。
  4. 组包成 42214 上报终端。

③ 举例

$BDTCI,发送方卡号,…,3,A4…十六进制…*hh
  → 编码类型 3（混编）→ 去 A4 → 十六进制还原 GBK → 转 UTF-8
  → 42214 上报终端："收到一条报文：……"
TCI 与 TCQ 是一对：TCQ 是"我发出去"，TCI 是"我收进来"，混编的编码/解码规则两边对称。

6 串起来看：一次完整的发报 + 收报

上电
每 5s 本机 ──$CCICR,0,00──▶ 模块        读卡：问卡能力
      本机 ◀──$BDICP,…卡号/频度/长度等级── 模块   拿到 bd_id / CD / maxlength，停止再问
每 1s 本机 ◀──$BDGSS + PWI── 模块    算 SQ(0~4) → status(在线/离线/异常)

终端要发报
终端 ──42212──▶ 本机 ──$BDTCQ,对方卡号,2,2,3,A4…,0──▶ 模块   TCQ：发射请求
终端 ◀──42213── 本机 ◀──$BDFKI,…,TCQ,Y,0,0── 模块          FKI：成功/失败回执

有人发报进来
终端 ◀──42214── 本机 ◀──$BDTCI,…,3,A4…── 模块             TCI：收报并转 UTF-8
记忆线：ICR/ICP（我是谁、能发多长、多久一次）→ GSS/PWI→SQ（现在信号行不行）→ TCQ（发）→ FKI（发成没）→ TCI（收）。读卡和 SQ 是"状态面"，TCQ/FKI/TCI 是"数据面"。
